# Two-host end-to-end validation: 2026-08-17

This record covers the first Supgang session between two physical computers. Private hive, node,
account, and network identifiers are intentionally omitted.

## Scope

- Candidate commit: `43e21829314950f7bc6bcc468447ef188b3bf444`.
- Binary SHA-256: `06b897b319d7a82f6f0d9c8be83caad58a633cd50cbf0be3343d58f569b27e4e`.
- Hosts: two Apple silicon computers running macOS 27.0.
- State: a new hive, a new identity on each host, and no reused preflight enrollment.
- Setup path: owner-controlled passwordless SSH to the designated account on the second host.
- Supgang path: direct QUIC over one globally scoped IPv6 candidate per host.
- External runtime services: none. The data path used no account, hosted discovery, DNS publisher,
  STUN service, vendor relay, or overlay network.

The hosts were on the same LAN and IPv6 prefix. This proves the two-host protocol and durable
recovery path, but it does not prove routing through a remote firewall, NAT, or CGNAT.

## Results

| Check | Result |
| --- | --- |
| Enrollment | The recipient-bound request and signed invitation produced one hive with two distinct nodes. |
| Local validation | Both `doctor` results reported strict mode and zero public dependencies. |
| Contact bootstrap | Each host accepted the other host's signed sequence-1 contact. |
| Authenticated session | Both hosts reported one active peer and one known peer. |
| Live convergence | Both views advanced to sequence 3 and contained direct plus authenticated reflexive candidates. |
| Second-host restart | The surviving host moved from one active peer to zero, then back to one within two polls. |
| First-host restart | The surviving host moved from one active peer to zero, then back to one on the next poll. |
| Tamper rejection | A changed contact was rejected on each host with exit code 3 and no accepted-state change. |
| Address privacy | Peer listings and process arguments contained no peer address. |
| Local protection | State directories were mode `0700`; files and control sockets were mode `0600`. |
| Process network use | Each running process held one UDP socket and no TCP socket. |

The services were restored after the negative tests and again reported one active peer on each
host.

## Limits of this evidence

- Endpoint candidates were supplied explicitly. Automatic discovery is not implemented.
- Both hosts shared a LAN. Wide-area reachability and difficult NAT behavior remain unproven.
- The service runs in the foreground. Boot-time service lifecycle is not part of M1.
- Keys use owner-only files. Hardware-backed providers are not implemented.
- Linux is covered by repository tests and CI, not by this physical-host run.

One-time enrollment, contact-transfer, and tamper-test artifacts were removed after acceptance.
The enrolled hive state, endpoint configuration, and installed binary remain on both hosts.
